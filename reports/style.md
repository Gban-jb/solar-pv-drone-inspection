# Solar PV Project Report Style

Status: **Locked by Sudin Pokharel, 2026-10-08.**

Use this format for every formal report or document produced for this project, including PDF and Word submissions. Keep the visual system consistent; adapt only the content and section structure to the assignment. Change the format only when Sudin explicitly requests a change. The canonical PDF layout is `reports/builders/layout.py`; each report keeps its own content script so it can be revised without recreating the design. Apply the same type, spacing, rules, and writing principles to Word documents.

## Page and type

- US Letter, 1-inch left and right margins, generous top and bottom margins.
- Black text on white paper. Georgia body at about 10 pt with comfortable line spacing; Avenir Next for title, byline, and section headings. Embed the fonts in PDF output.
- One modest, bold title. Below it: student name on one line, then project, instructor, and date in plain text. No cover page for a short report.
- Numbered, descriptive section headings. Use a thin black rule under the title block and section headings, and a light rule above the page number in the footer.
- Plain paragraphs and short labeled lists when helpful. Tables only when values genuinely need side-by-side comparison.
- References at the end using numbered citations in the text. Links may be clickable but remain black in print.
- No accent colors, shaded boxes, heavy borders, icons, oversized headings, or filler graphics. Rules should be hairline weight and only help separate content.

## Writing

- Write like a student explaining work to a professor: specific, direct, and modest about what is known.
- Use the assignment's technical terms where they matter; explain them in ordinary language on first use.
- State completed work, proposed work, and open questions distinctly. Never imply a test or dataset exists when it has not been verified.
- Prefer concrete observations and decisions over generic promises. Avoid promotional language, slogans, and repetitive "What I..." headings.
- No em dashes. Use ordinary punctuation and simple sentences.
- Keep short phase reports around two pages. Expand only when results, methods, or the assignment require it.

Before delivery, render every page and check that it is legible, unclipped, and consistent with this style.
